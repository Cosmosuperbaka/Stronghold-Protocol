## 0. 通用约束

- 所有主机功能只放在本机控制台（`127.0.0.1`，token + Host 校验）。游戏端口会经隧道公开且没有鉴权，不得新增任何管理入口或数据接口。
- 不改变战斗规则、生成数据和 golden。对局逻辑里不用 `Math.random` / `Date.now`，随机走 `m.rng*`，计时走 `m.later` / `m.setDeadline`。
- 给 `Match` 加回合内会变的字段时，同步 `server/match/rewind.js` 的 `MATCH_KEYS`，并跑 `node --test test/match/rewind.test.js`。
- 服务端新增的中文提示要用 `N_()` 标记，或按现有方式标注 `i18n-ignore`；玩家界面的新文本补齐四个语言包。
- 每项功能都要有针对性测试；涉及页面的要在空闲端口（例如游戏 3005、控制台 3105）实际预览验证。不引入新依赖。
- 完成后更新 LOCAL-DEV（实现）、LOCAL-CHANGELOG（玩家视角）、README「本库特色」和 HANDOFF 功能表。
- 建议顺序：1 → 9 → 8 → 4 → 5 → 6 → 3 → 2 → 7（先做低风险、复用度高的部分，重启恢复放最后）。

## 1. 控制台聊天管理

**目标**：主机能看到并管理各房间的文字聊天，能向玩家发系统公告。

- 房间卡片增加「聊天」面板，显示该房间最近的聊天记录（与玩家看到的 50 条一致），实时刷新。
- **系统公告**：主机输入文字，发送到指定房间或全部房间。玩家端以区别于普通消息的样式显示（例如「主机公告」标签、不同颜色），不受玩家发言频率限制，长度上限与普通消息一致。
- **清空聊天**：清空某房间的聊天记录，在线玩家的聊天窗口同步清空。需要确认。
- **禁言**：对某名玩家禁言 / 解除禁言，房间内有效，直到房间关闭。被禁言者发送时收到明确提示。观战者本来只读，不涉及。
- **踢出**：将某名玩家或观战者移出房间，复用现有的踢人 / 移除观战者逻辑；对局中踢出按现有「离开」规则处理。需要确认。
- 以上操作都写入控制台操作日志。

**验收**：公告、清空、禁言、踢出各有服务端测试；玩家端能区分公告和普通消息；游戏协议里没有任何新入口能触发这些操作。

## 2. 多人监控墙

**目标**：主机在一个页面上同时看到一个房间内所有玩家的概况，不必逐个打开实时页。

- 从房间卡片打开「监控墙」页面，按座位排成 2×2（不足 4 人时留空）。
- 每格显示：玩家名、LP、金币、商店等级、当前阶段 / 回合、是否已准备、是否托管或掉线、棋盘缩略（作战区 4×9 格中每格的干员名或头像，精锐标记）、激活的盟约及层数。
- 刷新频率与现有实时页相当（约 1 秒以内）。点击某格打开该玩家的现有「实时查看 / 代操作」页。
- 监控墙只读，不提供代操作。
- 不要求在监控墙里渲染完整的游戏画面或战斗；如果实现上能做到轻量的战斗缩略可以另议，但不是本期要求。

**验收**：4 人房间下页面持续运行 30 分钟无明显内存增长；阶段切换、玩家淘汰、对局结束时显示正确。

## 3. 资源面板

**目标**：主机了解服务器负载和每个玩家的网络状况，判断卡顿来自服务器还是网络。

- 控制台新增「资源」标签或顶部状态区，显示：
  - 进程：运行时长、内存（RSS / 堆）、CPU 占用的近似值。
  - 连接：在线会话数、房间数、进行中的对局数、观战人数。
  - 流量：游戏 WebSocket 的发送 / 接收速率（总计与按房间），静态素材的发送速率。
  - 延迟：每名在线玩家到服务器的往返延迟（RTT），有异常高值时醒目提示。
- 数据最多保留最近 10 分钟，以简单曲线或数字显示，不持久化。
- 统计本身的开销要很小，不能因为采集流量和延迟而影响对局。

**验收**：有测试证明计数在发送 / 接收后正确增长；延迟测量对玩家端无可见影响；关闭控制台（`SP_ADMIN=0`）时不采集。

## 4. 漏怪分析

**目标**：回答「哪些敌人漏得最多、哪一回合漏了什么」。

- 本局统计和对局记录详情里增加「漏怪」视图：
  - 按回合：每名玩家这回合漏了哪些敌人、各几只、其中计入扣血的数量、实际扣血。
  - 按敌人：整局累计，各敌人漏了几只、出现在哪些回合，按数量排序。
- 敌人显示名字，不显示内部 key。
- 区分普通战斗、联防和领袖战（最终攻势 / 隐秘核心）；领袖战的口径与普通回合不同时要单独说明。
- 需要在每回合记录里保存漏怪明细（目前记录里只有漏怪数）；旧记录没有明细时显示「旧记录无漏怪明细」，不推算。

**验收**：测试覆盖一回合多种敌人漏怪的汇总、回档后被放弃回合的漏怪不保留、旧记录的兼容显示。

## 5. 跨局汇总

**目标**：在「对局记录」页看到所有已保存对局的总体统计。

- 「对局记录」页顶部增加总览，读取 `logs/results/` 中的所有记录：
  - 总局数、胜率；按模式（独立 / 同盟）和难度分组的胜率与平均到达回合。
  - 最常用的干员、最常激活的盟约（按出现局数）。
  - 伤害最高的干员（累计和单局最高）。
- 支持按时间范围和模式 / 难度筛选。
- 只读文件，不修改记录；损坏或字段缺失的记录跳过并计数提示，不让整个页面失败。
- 记录很多时（例如 1000 局）页面仍能在几秒内打开，可以做缓存。

**验收**：用若干构造的记录文件（含旧格式和损坏文件）测试汇总数字。

## 6. 经济明细和盟约层数曲线

**目标**：逐回合看到每名玩家的钱怎么来、怎么花，以及盟约层数怎么变化。

- 每回合记录增加经济明细：本回合收入（按来源分：回合基础收入、利息、悬赏、出售、主机调整等，以现有代码能区分的来源为准）、支出（购买、刷新、升级等）、刷新次数、购买 / 出售次数。必须在回合计数清零之前记录。
- 每回合记录增加各激活盟约的层数和当前档位。
- 控制台曲线新增指标：「本回合收入」「本回合支出」「盟约层数」（盟约层数需先选择盟约或玩家）。遵循现有图表约定：一次一个指标、不用双 Y 轴、座位颜色固定、可切换表格。
- 逐回合详情表中展示同样的明细。
- 回档后数据与那个休整期一致，被放弃的回合不保留。旧记录缺少这些字段时显示为空，不推算。

**验收**：测试覆盖收入 / 支出合计与玩家实际金币变化一致、回档截断、旧记录兼容。

## 7. 重启后恢复对局

**目标**：服务器重启（包括控制台重启和自动更新）后，进行中的对局能回到最近一个休整期开始，玩家重连后继续。

- 每次进入休整期时，把恢复对局所需的完整状态写入 `logs/` 下的文件（每个对局一份，覆盖旧的）。对局结束或房间关闭时删除。
- 服务器启动时读取这些文件，重建房间和对局，停在保存的那个休整期开始，倒计时重新开始。
- 玩家用原浏览器打开页面时回到原座位（沿用现有的重连身份）；在原有重连时限内没有回来的玩家按现有掉线规则处理。AI 座位正常继续。
- 保存的状态必须带版本指纹（应用版本、模拟器 / 数据内容）。指纹不一致时不恢复，在控制台列出「因版本变化无法恢复的对局」，并提供删除。
- 恢复后重打的结果必须与不重启直接打的结果一致（与现有回档的等价性要求相同）。
- 回放录制在恢复后继续，作废时间线的处理与回档一致。
- 控制台「设置」里提供开关「重启后恢复对局」，默认开启；关闭时行为与现在一致（重启结束所有对局）。
- 控制台的「重启服务」和更新确认框要说明：开启恢复时对局会回到本回合休整期开始，而不是结束。
- 恢复对局会改变玩家可见行为，开工前和维护者确认细节（例如作战中途重启时，本回合是否重打）。

**验收**：测试覆盖「保存 → 模拟重启 → 恢复 → 继续打完」与「不重启直接打完」结果一致；版本指纹不一致时拒绝恢复；损坏文件不影响启动；关闭开关后不写文件。

## 8. 空闲时自动更新

**目标**：有新版本时，服务器在没有进行中的对局时自动安装，主机不用守着电脑。

- 「设置 → 版本更新」新增选项「空闲时自动安装新版本」，默认关闭，重启后保留。
- 开启后服务器定期检查本库正式 Release（间隔不短于 1 小时，遵守现有的代理 / 镜像配置）。发现新版本后：
  - 没有进行中的对局时，走现有的下载、签名校验、备份、安装、重启流程。
  - 有进行中的对局时等待，直到全部结束；等待期间不打断对局。
- 只自动升级到比当前更新的正式版本，从不自动回退；签名校验失败时停止并在控制台提示，不降级。
- 安装前向所有房间发系统公告（依赖功能 1），例如「服务器将在 1 分钟后更新并重启」。等待公告期间有新对局开始时，取消本次安装，等待下次空闲。
- 控制台显示自动更新状态：上次检查时间、发现的版本、正在等待空闲 / 正在安装 / 失败原因。
- 外部 supervisor 管理的部署沿用现有重启限制。

**验收**：测试覆盖有对局时等待、空闲时安装、不回退、签名失败不安装、公告期间有新对局时取消。

## 9. 更新后弹出更新记录

**目标**：升级后第一次打开游戏或控制台时，告诉玩家和主机这一版改了什么。

- 游戏端：版本变化后第一次打开时，弹窗显示 LOCAL-CHANGELOG 中当前版本的那一节。只显示面向玩家的内容，不显示验证和测试数据。玩家关闭后，同一浏览器在同一版本下不再弹出。首次安装（没有旧版本记录）不弹。
- 控制台端：更新重启后第一次打开控制台时，显示同样的内容，可附带「完整更新记录」链接。
- 弹窗可用 Esc 和关闭按钮关闭，手机横屏可正常阅读和滚动。
- 内容来自发布时随包提供的数据（例如打包时从 LOCAL-CHANGELOG 生成），不在运行时联网获取。
- 内容为中文时，其他语言界面显示中文原文并注明「仅提供中文」，或由维护者另行提供译文。

**验收**：测试覆盖版本变化时弹出、同一版本不重复弹出、首次安装不弹；浏览器测试覆盖桌面和手机横屏布局。
