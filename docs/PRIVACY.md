# 本地数据与公开前检查

本项目可在自己的电脑上开服。源码、游戏素材、主机记录与浏览器数据分别存放，分享仓库时应检查 Git 实际跟踪的内容。

## 数据存在哪里

| 数据 | 位置 | Git 处理 |
|---|---|---|
| 主机对局记录 | `logs/results/`，可能包含玩家名字、房间码和对局统计 | 整个 `logs/` 被忽略 |
| 主机整局回放 | `logs/replays/`，包含名字、playerId、房间码、实际阵容、敌人、结果和控制台操作摘要 | 整个 `logs/` 被忽略，不进入发布包 |
| 主机设置与日志 | `logs/admin-settings.json`、运行日志 | `logs/` 和 `*.log` 被忽略 |
| 游玩统计 | 浏览器 `localStorage` 中的 `sp.pref.stats`，包括同局玩家名字 | 不属于仓库文件 |
| 调配、皮肤、偏好与恢复身份 | 玩家浏览器本地存储；皮肤为 `sp.pref.skins` | 不属于仓库文件 |
| 手动导出的统计与调配文件 | `stronghold-stats-*.json`、`stronghold-loadout-*.json`、`stronghold-ownership-*.json`、`stronghold-diy-*.json` | 对应文件名被忽略；改名后需另行检查 |
| 素材与缓存 | `public/assets/`、`public/fonts/`、`public/vendor/`、`data/local-assets.json`、`.cache/` | 被忽略；生成的数据表与源码仍保留 |
| 本机界面审查产物 | `.impeccable/` 中的截图与报告 | 整个目录被忽略，不进入发布包 |
| 本机配置与凭据 | `.env`、`.env.*`、`scripts/service.env.cmd`、frp 配置、密钥、`.npmrc`、`.cloudflared/`、shell 历史等 | 被忽略；已审核的 `.env.example` 与 `.env.*.example` 可提交 |
| 私人笔记、快捷方式与浏览器资料 | 根目录 `private/`、`local/`、`secrets/`、`handoff/`，`*.lnk`、`*.url`、浏览器 profile、HAR、认证缓存 | 被忽略 |

主机回档快照存在服务进程内，重启后消失。浏览器数据按站点来源分别保存；清理浏览器站点数据会丢失本机统计、偏好和恢复身份，清理前可按需导出。导出文件可能含个人信息，请自行保管。

## 忽略规则的边界

整局回放只在主机本地存储，不上传，不提供公网分享；默认保留最近 50 局，自动清理仅删回放。控制台设置可关闭录制（活动对局也停止并不保存回放），记录页可删除单局结果与关联回放，设置页可分别清理对局结果、回放和控制台操作日志。素材、主机设置、更新包和浏览器数据不受这些清理操作影响。活动对局结束后仍可产生新记录，操作后也可产生新日志；详见 [LOCAL-DEV.md](LOCAL-DEV.md) §5。

`.gitignore` 防止未跟踪文件在普通 `git add` 时被加入；`.dockerignore` 防止对应本机文件进入 Docker 构建上下文。它们不是内容脱敏工具：

- 已经跟踪的文件仍会被提交，`git add -f` 也能绕过忽略规则。
- 文件删除或改写后，旧内容仍可能存在于历史提交、其他分支、标签、PR 和发布附件中。
- 作者和提交者邮箱属于 Git 提交元数据，不受忽略规则控制。需要保护邮箱时，在后续提交前使用 GitHub 设置页提供的 noreply 邮箱。
- 任意命名的截图、压缩包和导出文件无法只靠文件名识别。不要把私人备份放进源码目录；确需暂存时使用上述忽略目录，并检查实际暂存内容。

## 公开或发布前

1. 检查 `git status --short`、`git ls-files` 与 `git diff --cached`；用 `git check-ignore -v <文件>` 确认新本机文件的规则命中。已跟踪的私人文件需单独停止跟踪，删除本机数据并非必要。
2. 检查准备公开的全部分支、标签及其可达历史，核对个人路径、玩家名字、房间码、私人服务器地址、账号、凭据及提交邮箱。当前文件干净不等于历史干净。
3. 如果发现历史中的隐私信息，先备份并确认受影响范围，再选择清理历史或创建经过审核的全新公开仓库。历史重写会改变提交哈希，需要协调现有协作者；不要未经确认执行强制推送。
4. 分享日志、导出或截图前另行脱敏；打包发布时使用项目打包工具，并检查文件清单与附件内容。源码忽略规则不适用于直接压缩整个目录。

主机控制台只监听 `127.0.0.1` 并使用 token；公网隧道或反向代理只转发游戏端口。不要分享带控制台 token 的链接，也不要把控制台端口公开到公网。
